# Journal

One dated entry per work session. The goal is an honest trace of the learning:
not only what got done, but what was understood and what is still unclear.

---

## Format

- **One file per session**, named `YYYY-MM-DD.md` (e.g. `2026-11-05.md`).
  If there are two sessions on the same day, add a suffix: `2026-11-05-b.md`.
- **Four sections, always in the same order.** Short bullet points are enough.
- **Written at the end of the session**, while it is still fresh.
- **Link to the code or notes touched** (relative paths), so each entry can be
  checked against the repo.

## Template

```markdown
# YYYY-MM-DD — <topic in a few words>

## What I did
- What I worked on, with links to the files (e.g. `../math/linear-algebra/linear_algebra.ipynb`)

## What I understood
- Ideas that now make sense, in my own words

## What is still unclear
- Questions, confusions, things I could not explain to someone else yet

## Next
- The first concrete thing to do next session
```

## Why

- **"What I understood"** is the proof of work: a model I can't explain is a model I don't own.
- **"What is still unclear"** keeps me honest and becomes the to-do list for review.
- **"Next"** makes the next session start in minutes instead of half an hour.
